# Hermes Execution Contract

This file is mandatory.

## Definition of done

A feature is complete only when:

- the implementation exists
- tests pass
- the feature works in a real run
- failure cases were tested
- documentation was updated
- security implications were reviewed
- screenshots, logs, commands, or test results prove the outcome

## Forbidden behaviour

Do not:

- report conceptual work as implementation
- create empty scaffolding and call it complete
- silently disable security to make a demo work
- hide failed tests
- rewrite unrelated code
- overwrite working repositories without backup
- install arbitrary external skills automatically
- expose secrets in logs, commits, screenshots, or prompts
- give agents unrestricted filesystem or shell access by default
- use multi-agent delegation when one agent is sufficient
- adopt a dependency without licence and maintenance review

## Change discipline

Every meaningful change must have:

- objective
- files changed
- rationale
- tests
- risks
- rollback method

## Milestone report format

MILESTONE:
STATUS: PASS / PARTIAL / BLOCKED / FAIL

COMPLETED:
- ...

EVIDENCE:
- commands
- tests
- screenshots
- file paths
- commit hashes

FAILED OR INCOMPLETE:
- ...

RISKS:
- ...

NEXT ACTION:
- ...

USER APPROVAL REQUIRED:
- yes/no
- exact reason
