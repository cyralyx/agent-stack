# Research Evidence Standard

Each material conclusion must distinguish:

- verified implementation fact
- maintainer statement
- roadmap claim
- user report
- inference
- proposal

## Source priority

1. source code and tests
2. official documentation and releases
3. maintainer issue or discussion responses
4. reproducible user reports
5. general community opinion

## Recency

Record access date and software version. Recheck claims before implementation when the project has released since the original evidence was collected.

## Sampling

Do not cherry-pick one complaint. Group duplicates, note opposing reports, and state sample size. Closed issues are not automatically resolved; inspect the resolution and current version.

## Output quality

Every adopted idea must link to:

- evidence
- licence analysis
- Cyralyx requirement
- implementation decision
- risk
